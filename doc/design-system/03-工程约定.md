# 工程约定

原则：**以后改起来代价大的现在定死；以后才需要的只留位置。** 开发主要由 AI 编写、你来审核，所以约定要写得足够具体，让每次交给 AI 的任务都能对照这里检查。

## 技术选型

| 部分 | 选择 | 理由 |
|---|---|---|
| 网站框架 | Nuxt 4 + TypeScript，静态生成 | 内容页是普通网页，SEO 和分享友好 |
| 场景渲染 | Three.js（Vue 封装可选 TresJS） | 网页上最成熟的 3D 库，体积小、加载快，和 Nuxt 共存 |
| 角色 | VRoid Studio 制作 → VRM 格式 → three-vrm 运行库 | 动画风人物、自带卡通着色（MToon）、换装 |
| 动画 | Mixamo 动作重定向到 VRM | 走、跑、待机、坐、互动 |
| 宠物、建筑、道具 | Blender（可先用 AI 生成粗模再修） | 统一卡通风格、导出 glTF |
| 内容 | Markdown（Nuxt Content） | 用 Git 管理，Obsidian 只作写作工具 |
| 双语 | @nuxtjs/i18n，中文在根路径，英文在 `/en/` | 每种语言一个网址 |
| 评论与留言板 | Giscus（GitHub Discussions） | 免费，不用自己的服务器 |
| 托管 | Cloudflare Pages | 免费、全球节点；Pages Functions 跑天气小函数 |
| 搜索 | Pagefind（构建时生成索引） | 纯静态 |
| 统计 | 不用 Cookie 的统计（Cloudflare Web Analytics 或 Umami） | 不弹同意框 |

## 仓库结构（pnpm monorepo）

```
kai-world/
├─ apps/site/               Nuxt：页面、路由、内容渲染、双语、SEO
├─ packages/
│  ├─ tokens/               tokens.json → CSS 变量、TS 常量、场景颜色表
│  ├─ ui/                   Vue 组件库（Kw*），Histoire 预览
│  ├─ world/                Three.js 场景：地形、光照、水、天空、天气粒子、角色、宠物、镜头、输入
│  ├─ env/                  时段、季节、天气的计算（纯函数，可单测）
│  ├─ content-schema/       内容 frontmatter 的 zod 定义
│  └─ utils/                与框架无关的通用方法
├─ functions/api/env.ts     Cloudflare Pages Function：大致位置 + 天气
├─ content/{zh,en}/         内容 Markdown 与附件
├─ assets/                  .blend 源文件、导出的 .glb / .vrm、贴图、AI 生成记录（提示词、参考图）
├─ data/                    本设计系统的 time-phases / seasons / weather
└─ docs/decisions/          决策记录
```

- `packages/world` 不依赖 Vue；只暴露 `mountWorld(el, options)` 和事件（靠近地点、互动、收集、切换场景）。页面用一个客户端组件按需加载它，内容页不打包它。
- `packages/env` 只做计算，不发网络请求，方便单测"某时某地应该是什么时段、季节、天气"。

## 变量只有一个来源

- 设计系统里的 `tokens.json` 和 `data/*.json` 是唯一来源，复制进仓库后生成：
  - `tokens.css`：`[data-light="noon|dawn|dusk|night"]` 四组 CSS 变量；
  - `tokens.ts`：类型安全的常量；
  - `world-palette.ts`：`world-*` 颜色转成 Three.js `Color`，按光照锚点索引，驱动天空、光照、雾和水的颜色。
- 根元素的 `data-light` 由当前时段决定；场景读同一份状态。界面和场景永远用同一份数值。
- 改值不改名；确实要改名时，旧名保留一个版本作别名，并写进决策记录。

## 环境：时段、季节、天气

流程：

1. 页面加载时先用访客浏览器的本地时间算出时段，立即渲染，不等网络。
2. 同时请求 `/api/env`。这个 Pages Function 从 Cloudflare 提供的请求信息里读出访客的大致经纬度、城市和时区（来自 IP，精确到城市级），再向 Open-Meteo 查询当前天气代码和气温，把结果返回给页面。
3. 页面用纬度判断半球和季节，用天气代码映射天气状态（映射表在 `data/weather.json`），渐变到真实天气。
4. 请求失败或超时（2 秒）时：季节按北半球日期，天气按季节概率随机，以访客本地日期为种子，同一天内保持一致。

约定：

- Open-Meteo 不需要密钥，非商业用途每天免费 1 万次，要求注明数据来源。函数按 0.1° 经纬度网格用 Cloudflare 缓存 30 分钟，实际调用量很低。页面角落注明"天气数据：Open-Meteo.com"。
- 不弹定位授权，不保存、不记录访客位置；函数只返回城市名、半球、天气，不返回精确坐标。
- 访客可以在 `WorldClock` 里临时预览任何时段、季节、天气，只影响本次浏览。

## 组件库（packages/ui）

- Vue 3 单文件组件，前缀 `Kw`，与本设计系统的组件页一一对应：`KwButton`、`KwTag`、`KwPlaceLabel`、`KwPlaceCard`、`KwContentCard`、`KwArticleHeader`、`KwWorldClock`、`KwTopBar`、`KwLangSwitch`、`KwDirectory`、`KwInteractPrompt`、`KwControlsHint`、`KwCollectToast`、`KwConstructionSite`、`KwEmptyState`、`KwWorldLoader`、`KwVisibilityBadge`。样式类名沿用 `kw-*`。
- 所有文字通过 i18n 键传入，组件里不写死中文或英文。
- 每个组件都要：只用变量、键盘可达、可见焦点、`prefers-reduced-motion` 降级，Histoire 预览覆盖四个光照主题和两种语言。
- 场景里的界面（地点标签、交互提示）也是这些组件。场景引擎发事件给出屏幕坐标，页面负责渲染；场景画面里不画界面文字。
- 页面里用到的 `Kw*` 组件一律在 `<script setup>` 里直接 `import`（`@kavian/ui/KwXxx.vue`）。`packages/ui` 在站点目录外面，开发服务器启动后新加的组件不会被自动发现；直接引入就不受影响。
- 场景每帧都在变的东西（提示跟着镜头移动的位置）不要放进 Vue 的响应式状态：引擎只在“出现 / 消失 / 换地点”时通知页面，位置变化通过 `onPromptMove` 直接改那一个元素的样式。否则整页每秒重绘 60 次。

## 通用方法

| 方法 | 做什么 |
|---|---|
| `resolvePhase(date, tzOffset)` | 按 `time-phases.json` 返回时段和四个光照锚点的权重 |
| `resolveSeason(date, lat?)` | 按半球和纬度返回季节；`|lat| < 15°` 返回常夏 |
| `mapWeather(wmoCode, region, season)` | WMO 代码 → 天气状态，山间以外的雪变成雨 |
| `fallbackWeather(season, dateSeed)` | 拿不到天气时的当日随机天气 |
| `useEnvironment()` | 汇总以上结果为响应式状态，同步到 `data-light` 和场景；支持临时预览 |
| `useInput()` | 统一键盘、触屏输入；输入框或面板获得焦点时暂停角色 |
| `useQualityTier()` | 按设备内存、WebGL 能力、省流设置和实测帧率给出 `high` / `low` / `preview` |
| `useReducedMotion()` | 读取系统偏好，统一关闭视差、光斑和粒子 |
| `sceneGraph` | 场景节点、出口、出生点；中英文地点名 |
| `queryContent(filter, locale)` | 内容查询，排除草稿和不可见内容，处理缺失翻译 |
| `collectibles` | 收集物登记与访客本地进度（`localStorage`，带版本号） |
| `persistPrefs` | 本地保存语言、宠物选择、音量、画质、最近场景；地图更新后位置失效就回出生点 |
| `formatMeta(locale)` | `2026.10.29`、`8 min`、`午后 15:40`、`28°` 等格式 |

## 内容模型与双语

```yaml
id: work-dive-log        # 稳定 ID，中英文共用，永不改
slug: dive-log           # 网址
type: work               # work | lab | note | life | page
title: 潜水日志
summary: 一年里 23 次下水的记录和装备笔记
date: 2026-10-29
tags: [潜水, 影像]
cover: ./cover.jpg
visibility: public
place: pier              # 可选：关联的场景或地点
```

- 中文放 `content/zh/`，英文放 `content/en/`，同一篇用同一个 `id`。缺少某种语言时，该语言的列表里显示标题并标注"仅中文 / Chinese only"，点进去看原文。
- 语言默认按浏览器语言，手动选择后记住。两种语言的页面互相标注（`hreflang`）。
- Obsidian 只作写作工具：在仓库的 `content/` 目录里写，或者把单篇复制进来。现有笔记库不迁移。

## 后端：需要什么、不需要什么

| 功能 | 怎么实现 | 是否需要自己的后端 |
|---|---|---|
| 内容、双语、搜索 | 静态生成 | 不需要 |
| 时段、季节、收集、偏好 | 浏览器本地计算和保存 | 不需要 |
| 真实天气 | 一个 Pages Function（约 30 行） | 只有这一个小函数，无数据库 |
| 文章评论、留言板 | Giscus，存在 GitHub Discussions | 不需要 |
| 访问统计 | Cloudflare Web Analytics | 不需要 |
| 以后的私密模块 | Cloudflare Access 保护某个路径 | 不需要写代码 |

以后如果想要完全自定义样式的留言板（比如码头信箱），再加 Cloudflare D1 数据库和一个函数，不影响现有部分。

## 权限预留

- 现在所有发布的内容都是公开的，不公开的东西不放进仓库。
- 预留两件事：内容字段 `visibility`（`public` / `unlisted` / `draft`），以及一个路由分组 `/private/`。将来要做不想公开的模块时，放进 `/private/`，在 Cloudflare Access 里加一条规则（例如只允许你的邮箱登录），不用改网站代码。
- 受保护的内容绝不能出现在公开页面的静态产物或前端代码里。

## 部署

- GitHub 仓库 → Cloudflare Pages 自动构建；每个分支有预览网址，合并到主分支才上线。
- 构建时检查：内容 frontmatter 校验、链接检查、无障碍检查（axe）、首个场景下载量预算。
- 域名买好后接入 Cloudflare，自动 HTTPS。

## 交给 AI 开发时

每个任务写清楚：要改哪个包、对照本设计系统的哪个组件或章节、验收条件（四个光照主题、两种语言、键盘操作、减少动态效果）。一次只做一件事，做完在预览网址上检查。

## 设计系统怎么迭代

- 版本号：改值是小版本，加组件或数据字段是次版本，改名或删除是大版本。
- 每次变化在这里改，同步到仓库，并在 `docs/decisions/` 写一条记录。
- 实现中发现规则不合理，回来改这里，不要在代码里悄悄偏离。
